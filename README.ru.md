# OpenRouter Web Search

Отвечает на встроенный инструмент харнесса `web_search` через
[серверный инструмент веб-поиска](https://openrouter.ai/docs/guides/features/server-tools/web-search)
OpenRouter, зафиксированный на движке **Parallel**.

Один вызов `web_search` превращается в один запрос OpenRouter Chat Completions, несущий
`tools: [{ type: "openrouter:web_search", parameters: { engine: "parallel", mode, max_results, search_context_size } }]`.
OpenRouter выполняет поиск на своей стороне и возвращает обоснованный ответ в
`choices[0].message.content` плюс стандартизованные аннотации `url_citation`. Провайдер отображает и
то и другое на `WebSearchResult` шва, поэтому штатный инструмент рисует ответ и его источники без
каких-либо изменений в инструменте.

## Установка

Клонируйте репозиторий в любое место на диске:

```
git clone https://github.com/nightfun-pixel/dsh-OpenRouter-search.git
```

Укажите менеджеру плагинов харнесса **абсолютный** путь к клонированному каталогу — `plugin_manager`
с `action: install_bundle` и `target: <абсолютный путь>`. Пакет устанавливается как запись `link:` в
активном профиле, поэтому правки в клоне вступают в силу при следующем запуске.

Перезапустите харнесс после установки. Host-половина (провайдер поиска и его схема `Config`)
монтируется из профиля; клиентская половина (карточка настроек) — это браузерный бандл, который
страница подхватывает при загрузке.

## Что изменила композиция

`cordis.patch.yml` вставляет строку провайдера и переопределяет строку `web`:

```yaml
- id: web
  name: '@deepseek-ai/dsh-web'
  config:
    searchProvider: openrouter
```

Это переопределение обязательно, а не косметика. Когда зарегистрированы два годных провайдера поиска
и ни один не выбран, шов роняет каждый `web_search` с `WEB_PROVIDER_AMBIGUOUS` вместо того, чтобы
выбрать один, — так что одна лишь регистрация провайдера сломала бы ту возможность, которую добавляет.

## Ключи не трогаются

Провайдер резолвит `OPENROUTER_API_KEY` через `ctx.credentials` — та же ссылка, которую строка
`llm-pi-ai` профиля уже использует для чата, — и откатывается на окружение запустившего процесса.
Вводить ничего не нужно, и никакой секрет в этом пакете не хранится.

## Настройки

Settings → Plugins → **OpenRouter search**:

| Что | Значения | По умолчанию |
| --- | --- | --- |
| Движок | `parallel` — фиксирован, показан для справки | `parallel` |
| Режим | `fast`, `advanced` | `fast` |
| Объём контекста поиска | `low`, `medium`, `high` | `medium` |
| Результатов на поиск | 1–10 | `5` |

Те же три поля есть и в собственном элементе настройки строки, сгенерированном из схемы `Config`
плагина; карточка — дружелюбнее из двух поверхностей.

Сохранение пишет переопределение в профильный `cordis.patch.yml`; *Reset to default* очищает его
обратно до слоя композиции, заданного патчем этого бандла. Namespace настроек — это id строки,
`openrouter-web-search`.

`max_results`, отправляемый в OpenRouter, — это **меньшее** из собственной границы инструмента и
сохранённой настройки, поэтому узкий вызов инструмента никогда не расширяется широкой настройкой.

## Настройка вне страницы настроек

Этот пакет ничего не импортирует, поэтому не экспортирует schemastery-`Config`, собранный
библиотекой, — схема представляет собой написанный вручную нативный граф. Значения, которыми карточка
не владеет, берутся из окружения, запустившего харнесс:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `DSH_OPENROUTER_SEARCH_MODEL` | `deepseek/deepseek-v4.1-flash` | Модель обоснования; должна поддерживать вызов инструментов. |
| `DSH_OPENROUTER_SEARCH_BASE_URL` | `https://openrouter.ai/api/v1` | База API; `/chat/completions` дописывается. |
| `DSH_OPENROUTER_SEARCH_API_KEY_ENV` | `OPENROUTER_API_KEY` | Ссылка на учётные данные, которую резолвить вместо неё. |
| `DSH_OPENROUTER_SEARCH_TIMEOUT_MS` | `120000` | Предел по настенным часам на один поиск. |

## Стоимость

OpenRouter выставляет счёт за поиск отдельно от хода модели. Parallel `fast` — $1 за 1000 запросов,
`advanced` — $5 за 1000, каждый включает до 10 результатов; токены модели обоснования оплачиваются
сверху. Измеренный поиск на `deepseek/deepseek-v4.1-flash` с `mode: fast` обошёлся примерно в $0.014.

## Классы ошибок

Ошибки несут открытый строковый `code` шва; сообщение называет исправление.

| Код | Причина |
| --- | --- |
| `WEB_PROVIDER_CREDENTIAL_MISSING` | Ни хранилище учётных данных, ни окружение не содержат ключа. |
| `WEB_PROVIDER_CREDENTIAL_INVALID` | OpenRouter отверг сохранённый ключ (HTTP 401/403). |
| `WEB_PROVIDER_QUOTA` | Нет кредитов (HTTP 402); поиск оплачивается даже для бесплатных моделей. |
| `WEB_PROVIDER_RATE_LIMITED` | HTTP 429; повтор вскоре безопасен. |
| `WEB_PROVIDER_TIMEOUT` | Превышен `DSH_OPENROUTER_SEARCH_TIMEOUT_MS`. |
| `WEB_ABORTED` | Вызывающий отменил поиск. |
| `WEB_PROVIDER_ERROR` | Всё остальное, с указанием используемых endpoint и модели. |

Поскольку этот бандл ничего не импортирует, его `WebError` — локальный класс, а не класс шва, поэтому
слой инструментов рисует их как `Error: <message>`, а не прикрепляет код к структурированным
метаданным ошибки. Сообщения написаны самодостаточными именно поэтому.

## Как вернуть обратно

Собственный `cordis.patch.yml` профиля применяется после каждого слоя бандла, поэтому он побеждает:

```yaml
- id: web
  name: '@deepseek-ai/dsh-web'
  config:
    searchProvider: deepseek-official
```

Удаление этого бандла тоже работает. Штатный провайдер DeepSeek в любом случае остаётся
зарегистрированным и нетронутым.

## Почему схема написана вручную

Бандл, установленный в профиль, резолвит голые спецификаторы из своего собственного каталога, который
не видит `node_modules` установки dsh, поэтому этот пакет не импортирует вообще ничего — включая
библиотеку схем. `Config` поэтому представляет собой нативный граф Schemastery, собранный вручную:
`Symbol.for('schemastery') === true`, строковый `type`, объект `meta`, volatile-узлы полей и
`toJSON()`, воспроизводящий сериализацию `{ uid, refs }` Schemastery. Это ровно те три вещи, которые
читает хост, — Cordis монтируется через `Config['~standard']`, `dsh-app-boot` проецирует через граф, а
`dsh-settings` пересобирает настоящую схему из `toJSON()`.
